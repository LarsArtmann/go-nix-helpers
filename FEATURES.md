| Status                    | Meaning                                                      |

## OCI container images (nix2container)

One-block image shipping via the `container` option — no Dockerfile, no docker
daemon. Bundled into the composite module (still 3 consumer inputs).

| Feature                                             | Status                | Notes                                                                                                                                                                                                                                                                                        |
| --------------------------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `container` option (19-key submodule)               | 🟢 `FULLY_FUNCTIONAL` | enable, packageName, registry, imageName, tag, entrypoint, cmd, user, exposedPorts, volumes, env, labels, extraPackages (list OR `pkgs:` function), pathsToLink, maxLayers, created, initializeNixDatabase, fromImage, fromImageEnv, nix2container; Linux-only outputs                                                                              |
| `packages.<package>-image` output                   | 🟢 `FULLY_FUNCTIONAL` | True OCI image spec — image.json + skopeo `nix:` transport; store-path layers shared across fleet images                                                                                                                                                                                     |
| `apps.<package>-image-load` / `-image-push`         | 🟢 `FULLY_FUNCTIONAL` | Daemon-less skopeo copy to docker daemon / registry; works with private Go deps (deps live in layers)                                                                                                                                                                                        |
| `checks.container-structure`                        | 🟢 `FULLY_FUNCTIONAL` | jq gate over image.json: non-root user, entrypoint, labels, arch, layers, config equality; container errors forced EAGERLY (`containerValidate` + `builtins.seq`)                                                                                                                            |
| Superb image defaults                               | 🟢 `FULLY_FUNCTIONAL` | Non-root `65532:65532`, cacert + `SSL_CERT_FILE`, auto `org.opencontainers.image.*` labels, `/bin/<mainProgram>` entrypoint (buildEnv relocation), volumes pre-created with `user` ownership (`mkVolumeDirs`), content-hash tag + zero-epoch `created` (byte-reproducible), `maxLayers = 20` |

| `checks.containerSmoke` (real backend)              | 🟢 `FULLY_FUNCTIONAL` | Self-hosted check assembling a REAL nix2container image and running the module's structure gate against the produced image.json; module tests stub the backend, this covers the n2c Go binary                                                                                                |
| `container.fromImage` / `fromImageEnv` base layers | 🟢 `FULLY_FUNCTIONAL` | Layered images over a base (e.g. distroless + data); passed to n2c `buildImage`; only base config.Env carries over (n2c at pinned rev 42d1df94); moduleTest-verified passthrough                                                                                                              |
