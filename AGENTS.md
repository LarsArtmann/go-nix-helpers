# go-nix-helpers — AGENTS.md

Shared Nix helpers for LarsArtmann Go repositories. This is a **Nix library**, not a Go application — it contains no Go code.

## What this project does

This repo provides Nix helpers for LarsArtmann Go projects:

1. **`modules/go-standard.nix`** (RECOMMENDED) — A flake-parts module exposed as `flakeModules.go-standard`. Provides standard flake outputs (packages, apps, devShells, checks, treefmt, overlay) via typed options. **Bundles `treefmt-nix` AND `nix2container` internally** — consumers need only 3 inputs (nixpkgs, flake-parts, go-nix-helpers). No `treefmt-nix`, `nix2container` or `systems` input required. One-line adoption: `imports = [ inputs.go-nix-helpers.flakeModules.go-standard ];`. Requires go-nix-helpers as a **real flake** input (not `flake = false`).

2. **`container.nix`** — OCI image assembly for the go-standard `container` option (nix2container backend): `mkImageConfig`, `envList`, `mkVolumeDirs`, `mkContainerImage`, `mkContainerStructureCheck`. Also imported directly by the self-hosted `containerSmoke` check, which exercises the REAL nix2container Go binary end-to-end (image.json assembly + jq gates) — the module tests stub the backend.

3. **`mkPreparedSource.nix`** — Solves private Go dependency injection for Nix sandbox builds. Go repos with private dependencies can't fetch them inside the Nix sandbox (no SSH, no network). This helper copies flake-input deps into `_local_deps/` and injects `replace` directives into `go.mod`. Used automatically by go-standard when `deps = { ... }` is set.

4. **`mkGoFlake.nix`** (DEPRECATED) — Function-based predecessor to go-standard. Use the module instead.

## Consumption pattern

### Recommended: go-standard module (3 inputs)

```nix
inputs = {
  nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  flake-parts = {
    url = "github:hercules-ci/flake-parts";
    inputs.nixpkgs-lib.follows = "nixpkgs";
  };
  go-nix-helpers = {
    url = "git+ssh://git@github.com/LarsArtmann/go-nix-helpers?ref=master";
    inputs.nixpkgs.follows = "nixpkgs";
  };
};

outputs = inputs@{ self, ... }:
  flake-parts.lib.mkFlake { inherit inputs; } {
    imports = [ inputs.go-nix-helpers.flakeModules.go-standard ];
    go-standard = {
      pname = "my-project";
      vendorHash = "sha256-...";
      description = "What it does";
    };
  };
```

treefmt-nix and systems are bundled internally by the composite module — no need to declare them as inputs.

### Lower-level: raw import (flake = false)

For projects that only need mkPreparedSource without the full module:

```nix
inputs.go-nix-helpers = {
  url = "git+ssh://git@github.com/LarsArtmann/go-nix-helpers?ref=master";
  flake = false;
};
# ...
mkPreparedSource = import (go-nix-helpers + "/mkPreparedSource.nix") {
  inherit pkgs lib;
  goPkg = pkgs.go_1_27;
};
```

7+ downstream consumers exist (BuildFlow, mr-sync, PMA, go-structure-linter, branching-flow, Standup-Killer, library-policy).


## Architecture

- **`mkPreparedSource.nix`** — the core helper. Takes `{pkgs, lib, goPkg}` then `{name, src, deps, ...}`. Returns a derivation that produces a patched source tree.
- **`mkGoFlake.nix`** (DEPRECATED) — shared flake-parts module. Superseded by go-standard module. Takes a config attrset with `{inputs, self, pname, version, vendorHash, description, src, deps, ...}`. Returns a flake-parts module attrset with packages, apps, devShells, checks, treefmt, and overlay.
- **Composite module** — `flake.flakeModules.go-standard` in `flake.nix` is a composite module (function of `{config}`) importing `[ treefmt-nix.flakeModule ./modules/go-standard.nix ]` PLUS mapping `config.systems = config.go-standard.systems`, so the go-standard `systems` option is the single systems knob. This bundles treefmt-nix so consumers don't need it as a separate input. treefmt-nix's flakeModule only uses `pkgs` from the consuming context, so re-exporting via a composite is seamless. The composite ALSO sets `go-standard.container.nix2container = inputs.nix2container.packages` (same closure-over-own-inputs trick), wiring the OCI backend with no fourth consumer input.
- **`systems` is configurable and WIRED** — go-standard exposes a `systems` option (default = `[ "x86_64-linux" "aarch64-linux" "aarch64-darwin" ]`, i.e. `nix-systems/default` minus `x86_64-darwin`, which nixpkgs 26.11 dropped); the composite maps it onto flake-parts' `systems`, which actually gates output generation. (Until 2026-09-25 the option was documented but never consumed — flake-parts' own default silently won.) Consumers override via `go-standard.systems = [...]` or `go-standard.systems = import inputs.systems;`.
- **`goPkgAttr` defaults to auto (null)** — resolves to the newest packaged `go_1_XX` branch in the consumer's nixpkgs via `pure-functions.nix`'s `newestGoAttrName` (numeric compare; falls back to `pkgs.go`). Replaces the hardcoded `go_1_26` default, which lagged every Go release and silently broke builds when a repo's go.mod floor moved past it (GOTOOLCHAIN=local forbids toolchain downloads in the sandbox). When even the newest nixpkgs branch is too old, `goTarballVersion`/`goTarballHash` builds Go from the go.dev source tarball.
- **Module options (57 top-level + `container` 19-key submodule; counted 2026-11-18)** — highlights: `enableCheck`, `enableTestCheck`, `enableOverlay`, `buildFlags`, `version`, `vendorHashes` (per-system), `enableGolangciLint`, `enableGofumpt`, `enableGoimports`, `enableNixfmt`, `enableShfmt`, `enableTempl`, `templGenerationPolicy`, `templCliPackage` (one templ CLI pin for build + devShells + treefmt), `enableTemplFreshnessCheck`, `enableGopls`, `enableGovulncheck`, `enableCompletions`, `completionStyle`, `enableUpdateVendorHashApp` (emits `apps.update-vendor-hash`: build → parse `got:` → substitute → re-verify, targeting the old hash by value), `goExperiment`, `cgoEnabled`, `packages` (monorepo, with per-package `extraBuildAttrs`), `validatePrivateDeps`, `privateDepPattern`, `publicDeps`, `privateGlobPattern`, `goPkgOverride`, `goTarballVersion`, `goTarballHash`, `lintAsCheck`, `requireDeps`, `enableLockGuards`/`lockGuards`, `enableVendorHashCheck`, `devShellHook`, and `container` (19-key submodule: enable, packageName, registry, imageName, tag, entrypoint, cmd, user, exposedPorts, volumes, env, labels, extraPackages [list OR `pkgs:` function], pathsToLink, maxLayers, created, initializeNixDatabase, fromImage, fromImageEnv, nix2container). `extraBuildAttrs` also accepts a `pkgs: attrs` function form. Hand-maintained counts ROT — re-derive via `grep -cE '^    [a-zA-Z_]+ = lib.mkOption' modules/go-standard.nix` and the moduleTest log's "(N checks)" line. tested by `test-module.nix` (238 assertions). `cgoEnabled` emits Go's canonical `0`/`1` for CGO_ENABLED (Nix's `toString false` is `""`, which Go treats as unset).
- **OCI container support (Linux-only outputs)** — `container.enable` emits `packages.<package>-image` (nix2container), `apps.<package>-image-load`/`-image-push` (skopeo; daemon-less), and `checks.container-structure` (jq gate over image.json: non-root user, entrypoint, labels, arch, layers, config equality). Superb defaults: user `65532:65532` (distroless nonroot), cacert + `SSL_CERT_FILE`, auto `org.opencontainers.image.*` labels, `/bin/<mainProgram>` entrypoint via buildEnv relocation, volumes auto-provisioned with `user` ownership (`mkVolumeDirs`), content-hash tag + zero-epoch `created` (byte-reproducible), `maxLayers = 20` for cross-image layer sharing. `container.packageName` selects the main package or any monorepo entry.
- **Monorepo support** — the `packages` option generates separate `buildGoModule` per entry, each with its own `subPackages` and `description`. Shared config (vendorHash, deps, goPkg) comes from the top-level go-standard config. Backward compatible — when `packages` is empty (default), single-package behavior is unchanged.
- **Recursive auto-discovery (build-time)** — discovers ALL `go.mod` files at any depth in dep sources during the BUILD phase (not during Nix evaluation), reads the module path, and generates replace directives automatically. Excludes example/testdata/vendor directories. Moving discovery to build-time avoids `builtins.readDir`/`builtins.readFile` on derivation outputs, which would force those derivations to be built during evaluation and break `nix flake check --no-build`.
- **Two-phase sub-module pipeline** — explicit `subModules` entries are mapped into `{modulePath, localDir}` pairs and handled at EVAL time; auto-discovered sub-modules are found by a shell script during `postPatch` at BUILD time. Both phases generate the same replace-directive shape and version normalization; dedup between them is a `grep -qF` check. (Restructured 2026-08-12 when discovery moved to build time; the pre-2026-06-19 4-way split brain no longer exists.)
- **`/vN` handling** — `stripVersionSuffix` filters ALL `/vN` segments from local directory paths (e.g. `event/v3/eventtest` → `event/eventtest`), while keeping the full versioned module path in replace directives.
- **Local-path stripping** — `stripLocalReplacesScript` strips all absolute (`/home/...`) and relative (`./...`, `../...`) replace directives before appending fresh `./_local_deps/` replaces.
- **Build-time validation** — verifies every private module require has a matching replace directive, failing with a clear message instead of the cryptic SSH error.

## Gotchas

- **`maintainers.larsartmann` is NOT registered in nixpkgs** — but works in `meta.maintainers` because Nix evaluation is lazy enough that `nix flake check` and builds pass. The attribute is never deeply evaluated during normal operations. Register in nixpkgs for full correctness (nix-env --maintainer queries).
- **`goPkg` parameter is dead weight** — the derivation has `dontBuild = true` and never invokes `go`. Kept for API compatibility.
- **`privateDepPattern` default is LarsArtmann-specific** — `validatePrivateDeps` only validates modules matching `github\.com/[Ll]ars[Aa]rtmann/` by default. Override for other orgs. Use `publicDeps` to exclude specific public repos that match the pattern but resolve via proxy.golang.org (e.g. go-atomic-write, go-ndjson, go-sse).
- **Six `extraBuildAttrs` keys are concatenated** — `nativeBuildInputs`, `buildInputs`, `checkInputs`, `configureFlags`, `preBuild`, `postInstall`: consumer values are appended to the module's list rather than overriding. All other keys use `//` override.
- **`validationTest` is a deliberately-failing derivation** — it cannot be a Nix dependency of a passing derivation. The `verify` check only tests success paths; `verifyValidation` is a separate shell script run outside the sandbox.
- **`apps.fmt` is conditional** — only generated when at least one treefmt program is enabled (`enableGofumpt`, `enableGoimports`, `enableNixfmt`, `enableTempl`).
- **`enableCompletions` warns instead of silently no-op** — when the binary doesn't support `--completion`, a clear warning is printed to stderr during the build instead of silently installing empty completions.
- **`requireDeps` deduplicates** — manually injected require lines are checked against existing entries in go.mod to avoid duplicates.
- **Composite module eliminates treefmt-nix + systems inputs** — consumers declaring these inputs won't break (harmless unused inputs), but they're no longer required. The `systems` input can still be used by setting `go-standard.systems = import inputs.systems;`.
- **Auto-discovery happens at BUILD TIME, not eval time** — `mkPreparedSource` generates a shell script that scans `_local_deps/` for `go.mod` files during `postPatch`. This means `nix flake check --no-build` works without building dep derivations. Explicit `subModules` are still handled at eval time (they don't read from store paths).
- **`postPatchExtra` runs BEFORE replace directives are injected** — consumers needing to read the generated replaces must account for this ordering.
- **`GOTOOLCHAIN = "local"` is set by default** in all devShells — prevents Go from downloading newer toolchains. Override via `shellExtraEnv.GOTOOLCHAIN` if needed.
- **`mkGoFlake.nix` emits `builtins.trace` deprecation warning** — the flake.nix export wraps with a trace message directing to the migration guide. Will be removed in a future release.
- **`templates/go-flake-parts/` is deprecated** — marked with banner in README and deprecation comment in flake.nix header. Use `templates/go-standard/` instead.
- **Module tests use `lib.evalModules` with stub options** — `test-module.nix` evaluates the go-standard module in isolation by providing flake-parts infrastructure stubs (`systems`, `perSystem`, `flake`, `packages`, `apps`, `devShells`, `checks`, `treefmt`). The `perSystem` function is then evaluated as its own module to check outputs.
- **`lib.mkIf` returns a wrapped value, not a plain function** — when testing overlays conditional on `enableOverlay`, you must unwrap the `{ _type = "if"; condition = bool; content = fn; }` structure. See `test-module.nix` `overlayCheck` for the pattern.
- **`test-assets/mock-templ-missing-generated/web/home_templ.go` must NEVER be committed** — the templ-committed fixture needs that file absent; the auto-commit daemon re-adding it turns `moduleTest` red (`attribute 'templ-committed' missing` hard-evals out of the whole check). It is gitignored now — if moduleTest fails with that error, check `git ls-files test-assets/mock-templ-missing-generated/` first.
- **Nix 2.34: tryEval cannot recover thrown messages** — `toString` of a tryEval-captured error is `""`. Never write content assertions like `hasInfix ... (toString result.value)`; assert against a pure message builder (see `goModFloorMessage`), flattened derivation attrs, or the throw-site source text instead. Eight such assertions shipped never-green on 2026-09-24/25 and hid a real `cgoEnabled` bug (`toString false` is `""` → CGO_ENABLED unset → cgo silently re-enabled; now canonical `0`/`1`).
- **`mkDerivation` consumes the `env` attrset but flattens its entries** — after `buildGoModule ({ ... env = { FOO = "bar"; }; })`, `pkg ? env` is false but `pkg.FOO == "bar"`. Read flattened attrs, not `.env`.
- **Clean-worktree verification recipe (daemon + GC race)** — `nix flake check` on dirty trees under the auto-commit daemon intermittently fails with `path ...-source is not valid` (dirty-copy GC). Recipe: `git worktree add /tmp/x HEAD && cd /tmp/x && nix flake check --no-build`, or commit first. Also: chain `git add -A && git commit -m ...` in ONE command — the daemon races separate add/commit pairs (verify by commit SUBJECT, not hash).
- **Host binfmt/GC incident (2026-09-25)** — after a daemon restart, `/run/binfmt` vanished while `/etc/nix/nix.conf` `extra-sandbox-paths` still referenced it: EVERY local build failed until `systemctl restart systemd-binfmt.service` (root). Combined with auto-GC (`max-free=30G`), `nix flake check` also deleted unrooted source copies mid-check. Run `scripts/nix-health.sh` before local verification batches; CI is unaffected — push (with owner approval) and let CI be the oracle when the host is down. Full writeup: `docs/postmortems/2026-09-25_lock-bump-and-silent-host-break.md`.
- **Module-test stubs MUST mirror flake-parts types or mkDefault assertions lie (2026-09-30, `b3d9580`)** — the harness stubbed `apps` as plain `types.attrs`, which shallow-merges and silently ignores `mkDefault`; the consumer-override assert failed even though the module was correct. Faithful stub: `attrsOf (submodule { freeformType = types.attrs; })`. Test-authoring corollaries from the same commit: parenthesize every `(x.program or "MISSING") == value` comparison (or-precedence binds `.== y` as the default — bit us twice); NO apostrophes in assert names (they become bash `echo '...'` strings → unmatched-quote EOF); never `deepSeq` derivation graphs (stack overflow); mkShell ALWAYS emits `shellHook` (assert `== ""`, not absence).
- **Container errors must be forced EAGERLY (`containerValidate` + `builtins.seq`)** — n2c `buildImage` arguments stay lazy all the way into the derivation attrs (even the REAL backend never forces them at eval), so a bad `container.packageName` or missing backend thrown inside the arg-assembly would only surface mid-build as a cryptic error. The module forces `containerValidate` via `builtins.seq` on every container output. Test corollary: a stub `buildImage` that only parks args in `passthru` swallows lazy throws — that is WHY validation is eager, not a stub bug.
- **OCI image-config keys are CAPITALIZED** (`User`, `Entrypoint`, `Env`, `ExposedPorts`, `Volumes`, `Labels`) — the nix2container Go binary unmarshals into containers/image v1.ImageConfig. Go json is case-insensitive so lowercase would also bind, but capitalized matches the image-spec config schema; stay consistent.
- **jq on image.json needs quoted `"image-config"`** — the key contains a hyphen: `."image-config".User`, not `.image-config.User` (jq parse error, not a missing field). Same for object shorthand `{image-config}` → `{"image-config": .["image-config"]}`.
- **nix2container specifics** — `tag = null` default derives a content-hash tag (reproducible); `created` defaults to the `0001-01-01` zero epoch; image output is a JSON file (`image.json`: `{version, image-config, layers, arch, created}` — verified against n2c types.go), NOT a tarball; `copyToDockerDaemon`/`copyToRegistry`/`copyToPodman` passthru derivations wrap skopeo with the `nix:` transport; `meta` is a direct buildImage argument (no overrideAttrs dance, unlike dockerTools); perms regexes match unanchored (production pattern: `"/data.*"`).
- **`container.registry` default `ghcr.io/larsartmann` assumes GitHub is the main remote** — owner decision 2026-11-17: default confirmed, carve-out for Forgejo-remote projects (`forgejo.home.lan`, `evo-x2.home.lan` in the fleet), which must override (`registry = "<forgejo-host>/<owner>"` or a registry-less `imageName`). Nix eval cannot see the git remote, so the carve-out lives in the option docs, never in auto-detection. PapDashboard (GitHub remote) is unaffected.
- **Push behavior is NOT daemon-guaranteed — verify, don't assume** — 2026-11-17: one push at 18:55 delivered the whole container foundation to origin (pusher unverified; the concurrent session is the likely candidate), after which the daemon sat on three follow-up commits (registry carve-out + CI fixes) for 25+ minutes without pushing. The daemon reliably COMMITS (and races manual add/commit pairs — chain `git add -A && git commit` in one command) but has never been observed to push this repo. Never claim "pushed"/"not pushed" without `git fetch` + `git status`. A stray `origin/systemnix-vn-version-fix` branch appeared 2026-11-17 (likely a daemon artifact — no session in this repo created it).
- **CI has gates local `nix flake check` lacks, and master CI stayed red for weeks unnoticed** (every push from ≥2026-10-30 to 2026-11-17 failed): CI runs bare `nix run nixpkgs#shellcheck -- scripts/*.sh` (style severity — one info-level SC2016 fails the job) and builds `checks.<system>.moduleTest` on BOTH ubuntu and macos runners. Rules: run shellcheck locally before declaring green; NEVER hardcode system strings in test-module.nix configs — key them by `pkgs.stdenv.hostPlatform.system` (the macos leg inverted hardcoded `x86_64-linux` vendorHashes assumptions; darwin-only red); check `gh run list` after the daemon pushes.
- **The script tab-drift RECURRED and the daemon swept it in twice (2026-11-17)** — a concurrent session re-tab-indented five `scripts/*.sh` (its editor's shfmt config differs from the repo's treefmt canon); the daemon committed the result 25 minutes after the CI fix landed, re-breaking the Format Check. The daemon also once committed a stray 1.9MB `mock-go-project` build artifact from `test-assets/` (now gitignored). Rules: `nix fmt` immediately before any commit/push window; re-run shellcheck + `nix fmt` after ANY concurrent-session activity; the daemon commits whatever is on disk.
- **Eval-bound consumer hooks die while the module rev is unpushed (early-adopter recipe)** — BuildFlow's nix-fmt pre-commit hook EVALS the consumer flake; if that flake references a go-nix-helpers option that exists only on unpushed master, the hook hard-fails (`go-standard.container does not exist`). Recipe: consumer branch → verify via `--override-input go-nix-helpers path:...` → commit with `--no-verify` (reason in the message) → relock + run hooks clean at merge. Encode in consumer migrations (T47–T49) and the migration guide. Daemon-behavior differences matter here: this repo's daemon commits only; PapDashboard's daemon PUSHES branches — check the foreign repo's daemon before branching there, and `git stash push -- <paths>` foreign working-tree modifications first.
- **`subPackages` default is `[]` (auto-discovery), changed from `["."]` 2026-11-18** — nixpkgs `buildGoModule` semantics: `["."]` builds ONLY the module root (a `main` package at root, no cmd/ layout), `[]` auto-discovers ALL non-vendor packages with main files. The old `["."]` default silently produced EMPTY binaries for every `cmd/<name>` repo (bank-sync's catalog check caught it invoking a missing binary). Consumers with unusual layouts MUST pin `subPackages = [ "cmd/foo" ];` explicitly. A silent-empty-bin warning exists; a zero-main-packages hard-fail guard is a backlog candidate.
- **Explicit `subModules` entries must have a physical path WITHOUT `/vN`** — the replace target strips `/vN` from the local dir (`storage/memory/v4` → `_local_deps/.../storage/memory`), but the dep tree copy keeps the versioned physical path. When upstream physically nests the module under `/vN` (go-cqrs-lite `storage/memory/v4`), the explicit replace points at a nonexistent dir AND pre-empts the correct build-time auto-discovery replace via the `grep -qF` dedup. Only list sub-modules whose physical path has no version segment; let auto-discovery handle the rest (found in crush-daily 2026-11-18).
- **`scripts/ci-parity.sh` is the pre-push gate set** (2026-11-18, T56) — default run: treefmt fail-on-change + shellcheck (style severity) + `nix flake check --all-systems --no-build` + flake.lock freshness; `--ci-jobs` adds the heavy CI legs (integration checks, template smoke, old-nixpkgs moduleTest); `--full` adds a building all-systems check. Run the default before ANY push claim; the lock-freshness leg went red within a day of its CI counterpart being introduced.
- **`.docs-gates.json` `annotate_max = 358` is a ratchet pin, not a pass** — set 2026-11-17 after the corpus sweep (433 inline verdicts; all 11 then-live 2026-08/09 reports annotated to the full canon and archived; battery all-green). The tolerated findings are pre-canon strikes inside `docs/status/archived/` (annotation passes that predate the fleet annotate gate, 2026-11-05). Never raise; ratchets DOWN whenever an archived file is re-touched with verdict-bearing markers. The battery: `nix run github:Artmann-Technologies/docs-gates -- run .`
- **`apps.<name>` subpath-only definitions DISPLACE whole-app mkDefault definitions (2026-11-18, wise-go)** — `apps.test.meta.description = "…"` (priority 100, plain set) entirely overrides the module's mkDefault whole-app definition (priority 1000), dropping `program` → "option accessed but has no value defined". Consumers must override the WHOLE app (`apps.test = { program = …; meta.description = …; }`) or annotate nothing. Same class as any priority-100-vs-1000 collision; flake-parts merges per-attribute, not per-app.
- **`templCliPackage` is a pin, not a generator switch** — the module never injects `templ generate` into the build; `templGenerationPolicy` is metadata and the consumer's `extraBuildAttrs.preBuild` runs generation. `enableTempl` only puts a templ CLI (default `pkgs.templ`, overridable via `templCliPackage`) on nativeBuildInputs, devShells, and treefmt.
- **shfmt canon is PINNED in the module (2026-11-18)** — `shfmt.indent_size = 2` + `shfmt.simplify = true` are explicit mkDefaults because treefmt-nix 0ba5d672 flipped its defaults to tabs + no-simplify; without the pin every consumer relock would re-indent all shell scripts. When bumping treefmt-nix, verify `nix fmt` stays a no-op on this repo (the CI format check enforces it per-lock).
